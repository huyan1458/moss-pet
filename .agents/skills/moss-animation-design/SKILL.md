# MOSS 宠物复现与定制

让没有参与原设计的人也能使用仓库恢复同版本 MOSS，或在明确的改动范围内继续设计。先分清用户要**使用成品**还是**改变成品**，不要把恢复任务变成重新制作。

## 找到任务所需的资产

用户提供分享链接时可直接走领养流程，无需寻找仓库。文件恢复或定制时，从当前项目或用户给出的目录定位含 `release.json`、`MOSS.png` 的仓库，读取根 README。不要依赖作者的盘符、账号、宠物 ID 或历史聊天。若素材仓库未提供，先完成不依赖它的说明或评审，仅在操作确实需要时询问位置。

| 用户目的 | 使用哪些资料 | 合格结果 |
| --- | --- | --- |
| 从分享链接领养 | 用户链接，或仓库 README / `release.json` 的公开链接；[runtime.md](references/runtime.md) | 领养为接收者自己的副本，按要求启用 |
| 恢复、导入、下载同版本 | `release.json`、`MOSS.png`，涉及应用时读 [runtime.md](references/runtime.md) | 使用原 PNG，不重绘；说明实际是否已导入/启用 |
| 改动作、灯光、外观 | [design.md](references/design.md)、[lessons.md](references/lessons.md)，改造型再读 [official-canon.md](references/official-canon.md) 并看相关原图 | 只改要求的部分，给出可用 PNG、预览及验证结果 |
| 排查触发或播放异常 | [runtime.md](references/runtime.md) 与当前版本的实际行为 | 区分素材、客户端和焦点/状态问题，不无故重绘 |
| 只讨论、评审 | 用户图像及相关参考 | 给出证据与不确定性，不自动修改或上传 |

## 恢复现有 MOSS

按用户选择使用分享链接或原 PNG。使用仓库链接前先读 `release.json` 的分享验证状态；网页预览可见不代表领养成功，有访问错误时明确说明并优先提供 PNG。用户要求领养且有当前 Pets 领养能力时，从实际链接提取工具要求的 `sharepet_` ID，成功后只用返回的新宠物 ID 进行启用或后续编辑。不把分享 ID 当作用户宠物 ID，也不借领养覆盖已有宠物。没有该能力时交付链接及可用的 PNG 备选，不冒称已领养。

核对成品文件与 `release.json`，直接使用它。PNG 已包含布局和动作帧，Blender、Skill、Python 都不是导入前提；“复现同版本”以成品 PNG 为准，不要求重新渲染。

如当前环境有 Pets 工具或对应插件，按其现有素材导入流程验证并导入。目标来自接收者自己的宠物列表：更新现有自定义宠物时保留该 ID；明确新增时才创建。是否启用遵循用户的要求。不把仓库文件名、作者账号或下载链接当作宠物身份。

没有可用导入能力时交付 PNG 和版本兼容说明，不能宣称已安装。当前成品是 v2 的 1536×2288；目标若只接受 v1，不裁掉方向行来冒充同版本恢复。

用户要求发布自己的分享链接时，按当前工具要求确认适用受众：个人分享链接公开，企业分享遵循工作区访问规则。链接只分享名称、简介和图集，不分享所有者身份。发布新版本后核对分享快照，不假定旧链接会自动更新。

## 定制 MOSS

先用一句话明确变化和需要保留的部分。仓库中的参数是当前设计默认值，用户的新目标可以改变它们；官方事实、模型近似和客户端能力限制则不能混称。

- 动作或灯效优先改 `config/animation.json`；形体、材质或绑定改 `assets/model/MOSS.blend`。脚本命令及参数见 [design.md](references/design.md)，不另造一套流水线。
- 默认保留 `MOSS.png` 成品基线，输出到 `build/`。只改一个状态时用 `--rows` 与 `--base MOSS.png`，确保其他格不被重渲染带入差异；改共享模型时统一渲染受影响状态。
- 动画中外壳、镜头、面板和支架保持刚体，只由对应关节带动，避免逐帧重绘造成尺寸或连接漂移。固定几何可以在建模阶段修改；不要把“刚体动画”误解为禁止用户调整模型。
- 用当前 3D 模型与固定贴图渲染动作，不逐帧生图。若用户明确要重新设计外观，可先生成或制作一次性资产，再绑定到同一个模型。
- 对尚无依据的机械结构采用最小工程假设并说明，不把经验参数写成电影规格。用户没要求时不新增关节或改变客户端。

先看实际192×208尺寸，再看放大细节。动作修改看原速预览；造型修改看无光束的正面、侧面、低头与遮挡关系。刚体检查证明没有逐帧变形，不能替代视觉判断。检查最终编码图的空格、透明边缘、光束远端及状态切换，不能只检查源模型。

修改与验收在用户已授权的范围内完成，不为普通本地编辑另设审批。用户要求上线时，展示最终预览、通过当前 Pets 结构验证后更新相应宠物；仅要求出稿时交付文件即可。

## 输出与经验维护

说明改了什么、交付文件、做过哪些验证，以及仍影响使用的限制。分别表述结构通过、离线视觉检查、真实客户端复验、用户认可，缺哪一项就不冒称完成。

新参数与用户偏好记录到当前项目；只有可复用且有证据的经验才更新对应参考文件。替换失效结论，不追加聊天流水账，不将一个人的偏好升级成所有 MOSS 的硬规则。

## 请求示例

- “通过这个分享链接领养并启用 MOSS。” → 领养后启用返回的新 ID，不上传或重绘 PNG。
- “用仓库的 PNG 恢复并启用同版本 MOSS。” → 核对文件、导入、确认启用，不渲染。
- “把悬停 J4 改成以待机为中心左右各5°，其他动作不变，先给预览。” → 改 row 4、局部渲染合成、比较未修改格，不上传。
- “输入框里有字，但没有低头扫描。” → 先确认有效状态和光标目标，不把客户端状态问题当成贴图缺失。
